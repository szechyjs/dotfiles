# Global Instructions for all projects

## Guiding Principles

- **Simplicity First**: Avoid unnecessary complexity, libraries, or build tools
- **Security**: Good security practices are non-negotiable
- **Testing**: Code should be well tested

## Workflow

- When making large changes, create a plan first and get feedback before implementation
- Code should be linted and tested after making changes
- Only commit changes if asked to do so, only include relevant changes, don't use `git add -A`
- Commit messages follow conventional commits format
- Don't use system `/tmp` directory for testing, use a temporary directory within the project instead
- Only work on one task at a time, don't switch between tasks unless asked to

## Code Style

- Only use comments when the code is not self-documenting

## Tools

- `dash` MCP provides offline docs for various languages and libraries
- `notion` MCP provides access to my Notion workspace which I use as a knowledge base
